# Discover and check coding agents

The collector saves every executable command name found on `PATH` in private `activity.json` as `cli_inventory`. It does not launch those commands. The names are an inventory to review, not a list of agents or proof of recent use. The collector also checks known local data directories for agents whose command is absent from `PATH`.

1. Read the entire `cli_inventory` and `sources`. Identify coding-agent candidates by command name, resolved executable location, local configuration, and the user's installed tools. Generic names can hide agents: for example, a command named `agent` may belong to Grok. Do not stop after the built-in readers for Codex, Claude Code, OpenCode, Factory Droid, Kimi Code, and Grok. If the user names a CLI supplied through a shell alias, app bundle, or path outside `PATH`, check that location separately and add its coverage status manually.
2. For any candidate missing from `sources`, rerun collection with `--agent-cli COMMAND` once per command. This registers the discovered CLI as `detected, unparsed`. Do this before adding hand-reviewed sessions or reset events to the activity file, since collection rewrites that file. The output path is printed by the collector and defaults to the user's application data directory, not the skill installation.
3. For each detected agent, look for local transcript, session database, or an official read-only usage view. Search only the relevant agent data roots, such as its home, XDG, or app support directory. Set its private `activity_in_window` field to `true` only after finding an event in the requested window, `false` after checking sufficient history to establish no activity, or `null` when activity cannot be determined. Check the recorded time, project identity, token units, cache semantics, and duplicate event behavior before adding a session to private `activity.json`. A command's presence alone does not establish usage.
4. Add a verified session with `agent`, `session_id`, `project`, `tokens` (`input_tokens`, `output_tokens`, `cached_input_tokens`) and short `prompts`/`final_messages` only when the source provides them. Use `tokens: null` when activity is verified but token counts are unavailable. Do not execute a prompt, start a new session, sign in, install a tool, or consume a usage allowance to make a report.
5. Keep the full per-agent audit private: counted with tokens, active with missing tokens, detected with inaccessible or unsupported history, or confirmed inactive. Put only verified active agents on the public card. If some sources remain unchecked, the card may show a generic coverage caveat, without listing unused or unverified CLI names. Do not claim all agents were counted when the inventory or their histories could not be checked.

Keep the command inventory and raw records private. The social card includes only reviewed, aggregate facts.
